# 网站入口、运动身份与会话

## 官方入口

|用途|入口|使用方式|
|---|---|---|
|跑兔体育后台|<https://www.ptty.com.cn/>|从首页登录，选择当前账户可用运动模块，再打开赛事管理；保留页面给出的路由|
|观众手机网页|赛事“比赛二维码”返回的网址|已观察形态为`http://wap.ptty.com.cn/wap/#/xmIndex?ssid=<平台返回值>`；使用完整原值，不拼接具体赛事标识|
|裁判微信小程序/PAD|比赛控制中的对应二维码|下载各自平台原图，用途不同，不能用观众网址替代|

后台是带`#/...`路由的应用；不要用手机域名的页面执行后台脚本。`ptty_readonly.mjs`只接受`https://www.ptty.com.cn/`后台文档、当前明文赛事ID和已观察组件。二维码导出同时校验官方手机域名、`/wap/`路径及`/xmIndex`赛事路由，并拒绝携带登录/临时下载参数；通过地址检查仍不证明页面已经可访问。

2026-10-06实测发现手机域名同一`/wap/`在HTTP与HTTPS下返回不同应用。处理这类问题时先保留二维码原始协议，检查最终URL、实际加载资源和路由，再回读目标赛事及报表。不要自动把HTTP改成HTTPS，也不要关闭浏览器安全功能或向HTTP观众页发送后台凭据。将“公开数据回读成功”和“手机浏览器展示通过”分别记录。此部署问题属于平台，更新skill只能正确识别和避开错误入口，不能声称修复了平台服务器。

## 运动身份检查

同一字段在不同运动应用中可能有不同含义。`QSLXID`是平台代码，不能从赛事名、字符串数字或另一运动模块的默认值推断。`SSLX`是单打/双打/团体等项目类型集合，也不是运动大类。

每次线上写入前同时核对：

1. 用户任务或交接包中的运动：`badminton / table_tennis / tennis / pickleball`。
2. 当前页面所选运动模块、表单的真实选项标签及值。
3. 目标赛事的明文ID、名称和读取到的`QSLXID/QSLXMC`。

出现冲突时先停止相关写入，保留只读调查及本地文件制作。查当前表单选项、模块入口和只读字典；只有确认修改字段不会迁移或破坏已有项目、且当前任务授权覆盖修正时，才按当前表单执行并回读。没有这种证据就明确报告未修复，不猜一个数字修改。不要借用其他赛事或自动新建替代。

`publication_packet.py`已经将这项检查用于每个请求预案：提供的运动文字、模块或选项矛盾时拒绝生成；缺少现场枚举时允许保存离线草案，但标记`sport_write_blocked:true`，每个动作保留身份待核实项。提供一致现场证据只证明该快照一致，执行前还要刷新核对。证据格式见[发布包](publication.md#离线发布包)。

## 登录与脱敏

优先复用用户当前登录会话。需要重新登录时使用受控浏览器输入或安全输入通道；本skill不提供默认账号，不把密码放命令参数、脚本、日志或版本控制。只读工具的`--session`是用户自行建立的本地CDP会话文件，存放在skill和公开仓库之外，退出后按任务需要清理。

平台业务ID、观众`ssid`不是密码，但能关联真实赛事；公开示例全部使用合成标识。真实报名表、姓名、手机号、证件、二维码、带签名下载链接、浏览器配置、Cookie和访问令牌只留在获授权的赛事资料目录。发布到Git前检查实际暂存文件与历史，不能仅依赖`.gitignore`。回执记录必要字段、哈希和差异，不打印完整请求头、会话或原始错误响应。

公开页面协议中的固定校验常量来自客户端代码，不是用户账号凭据；如平台更新协议，重新观察页面合同，不读取或收集无关用户身份信息。
