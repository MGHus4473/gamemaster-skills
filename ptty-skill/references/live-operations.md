# 现场、成绩、权限与财务

按任务查看本页及操作目录。接口名称是定位线索；参数、模式和权限须从当前页面确认，不直接凭名称发请求。

## 名单与报名

- 报名管理分项目配置、人员、单位、项目报名、团体成员、概况、会员优惠审核和交易记录。项目调组不等于方案并组；团体需检查全队成员。
- 报名配置包含性别/出生日期校验、年龄和、个人与团体人数上限、跨组/兼项、头像、收费/退款审核、优惠、白名单/黑名单及收款渠道。保留未修改项；出生边界和收费单位必须与规程一致。
- 报名期间页面限制直接操作竞赛名单时，回到报名管理；不绕过限制。全局人员姓名修正可能同步单打、双打、混双报名。局部替补不能冒充全局改名。
- 锁名单可能扣余额。先读取报价及是否已锁定，再按既有费用授权执行；超时先确认锁定和扣费事实，不能反复点击。

### 局部替补

2026-10-08合成实测通过的入口为名单管理中当前可见“修改人员信息”：前端`updateRyxx(row,'UPT')`初始化表单，后端`rmdGl/newSaveUpdateRyxx`保存。旧`tableRmdSave → rmdGl/updateRyxx`的`UPTTYPE:0`返回数据错误，且未找到当前按钮调用旧`tableRmdEdit`；不要用残留方法推定有效入口。

1. 保存全项目名单、签位、方案、编排和比分，明确替换哪一报名项、哪位成员及候选资格。读取候选的真实身份；同名不足以确认同人。已完赛或下游已录分时，先明确结果处置范围，不能自动继承原选手比分。本次清分与恢复仅是获准的合成测试，不作为真实临场换人的默认动作。
2. 单打当前表单保留`XMID、XMNM、SSLX、TYPE:UPT、ZZH、DNJSH`等原值，仅用候选对应信息填写`DWQC1、DWJC1、RYXM1、XB1、SFZH1、AGE1、TEL1`。当前表单不含`RYID`，不自行添加它或旧`UPTTYPE`。`getTzrmd`可读取同队候选；`scripts/roster_replacement.py`的`prepare(form,candidate)`离线复制表单，不提交线上操作。
3. 保存后全量回读所有项目：同一`XMNM`必须绑定候选实际人员ID（单打`RYID`，双打`RYID1/2`），并核对身份资料、种子及其他报名项。已有兼项的候选应复用同一人员ID；仅改姓名、另建同名身份或改变兼项均不算通过。`audit(before,after,project_id,entry_id,candidate,member_index=1)`检查完整名单中的局部重绑定和非目标项不变；CLI接受同名JSON字段。名单检查不代替签位、比分和编排验收。
4. 编辑可能使名单锁定失效，抽签查询会返回“未锁定名单”。查询失败或字符串错误不是空签表，也不能用于前后相等比较。先读取当前锁定报价，沿用已有适用授权；费用/范围变化按实际授权处理。恢复锁定后再读签位、赛程和排名，不自动重抽或重新生成比赛。
5. 用新身份重新绑定本地兼项映射，复核完整人员冲突、休息及晋级依赖。换回原姓名时也要回读：实测既有重新分配`RYID`的情况，也有原人员仍参加单打、换回双打时复用原ID的情况；不能由姓名或成员位置推断平台身份复用规则。核对同人其他报名项，按实际差异记录旧→新ID关系并刷新映射和赛果身份快照。报告区分业务恢复与标识变化。

**双打换搭档**：先明确替换第一位还是第二位成员，不能按“左边/右边”推断；对阵左右方与组合内成员序号是两个维度。当前表单仍用同一保存接口，只修改指定成员的七个人员字段（例如第二位用`DWQC2…TEL2`），原样保留另一位全部资料、报名项及种子。`prepare(form,candidate,member_index=2)`与`audit(...,member_index=2)`可处理第二位；第一位显式传`1`。工具检查另一搭档不变、候选未占据同项目另一组合或本组合另一成员位、其他项目报名不变。特殊三人/轮转双打及团体不得按普通二人双打处理。

替补后的录分按当前双方**完整成员组合**绑定，不能因报名项`XMNM`没变就复用旧比分。先解决受影响旧赛果，再录入有明确来源的新赛果；逐轮核对人员传播与名次。合成实测已完成第一位替补组合半决赛获胜、决赛夺冠，官方成绩导出与独立复算一致，单打名次未变。恢复原组合前先按测试方案清除新赛果，再恢复原组合及原比分；这是测试恢复流程，不代替真实比赛的赛果裁定。

已验证范围：已锁定且已有签位、赛程的单打换成同队现有双打选手，以及男双第一、第二位分别换成同队现有单打选手；原搭档及双方兼项、种子、签位均核对。受影响结果按测试方案处理；未据此验证女双/混双、团体、跨单位、新增人员或保留既有比分的直接替补。工具支持字段形态不等于所有模式已线上通过。

## 签到、检录、人员与场地

- `/qdGlIndex` 的 `rmdDataBaseGl/qdHandler` 修改人员签到，使用页面取得的人员标识和 `ISQD`；它不等于某一场次的检录、上场或录入成绩。
- 检录屏含 `jlSave` 写操作；显示屏并非一律只读。比赛控制的检录提醒、手动通知及“测试通知”也会影响真实对象。
- 控场先按项目、场次、场地、小节定位，回读双方、状态和时间。临时调场 `kcGl/lsDcSave` 后检查原/新场地占用及相关屏幕，不自动重生成场次。
- 团体出场名单读取 `teamRmdData`，保存 `teamRmdSave`，清除 `teamRemoveRmdSave`；设定拉取/锁定、公开隐藏、调整团体场次顺序、特殊团体设置分别处理。先核对本场名单、场数、兼项和队员资格，不能用整队报名名单代替每场出场名单。
- `hjCpzOrDyGl/GetHjxxList` 是呼叫列表，`hjClSuccess` 是处理完成，不能在查看时自动消除呼叫。

## 比分与弃权

控场使用 `markGl/adminUpdateMark` 修改、`adminRemoveMark` 清除、`adminRemoveMarkBatch` 批量清除。修改前核对双方顺序、逐局比分、获胜方、计分模式、弃权/判罚状态及受影响下游。页面要求英文冒号/逗号的字段按实际格式填写；合法比分按赛事所用规则检查，不能写死一种运动比分。

已验证的单打录分读取链为`kcGl/getDjMark`→`kcGl/getMarkMx`：从当前响应取得`XMID、CCH、SXH、ZJS、XMNM1/2、SSLX、BZFS`，不从场序或姓名构造身份。该单打响应的两方姓名位于`RYXM1/RYXM3`，不能误取空的`RYXM2`；其他项目按实际成员结构核对。逐场提交后回读明细，待胜负者传播确定下一轮双方后再填下一场。后台录分的开始/结束时间可能仅反映录入操作，不能用于证明运动员已满足实际休息。

复杂合成赛已验证双打该响应的左方为`RYXM1/RYXM2`、右方为`RYXM3/RYXM4`，须核对双方完整组合和报名项映射。两阶段交叉可能保持同一对阵但左右顺序与本地相反：先保存当前双方与本地双方的映射，只有两侧完整身份恰好互换时才按对应侧转换逐局比分及侧别字段，保留原始值和转换记录；人员或搭档不同则停止，不改签表来迁就旧比分。转换后重新验证胜者和下游。实测的两组AB签位为A1、B2、A2、B1，不将此顺序推广到其他分组数量或模式。

当前页面说明单场弃权和“一弃到底”影响不同，部分模式会使记录不参与排名；全名次淘汰也有专门提示。保留原始状态，按当前配置和规程选择，不能把所有弃权都转成同一个比分。若页面要求先取消判罚再清分，需把这两步的影响纳入原授权与回读。

清除比分与更正比分分开。比分改变后检查胜负者晋级、下游双方、下游是否已开赛、循环排名、最终名次及已发布成绩；已进行的下游赛事出现冲突时，先提出具体处置方案。系统自动传播不能凭成功提示推定。下载最终成绩仍走[报表工具](read-only.md)，必要时交离线 skill 独立核算。

当前单场清分`adminRemoveMark`使用`XMID、CCH、SXH、SSLX`；不能用录分请求的字段子集替代。单场弃权枚举已观察`L-DCQQ/R-DCQQ`，取消为`DCQQ_Remove`，与`L-Ret/R-Ret`一弃到底不同。请求双方用`PFLX:"左值&右值"`，`czlx:"DCQQ"`；仅用于当前已核验单场合同。实测单场弃权返回`0:21`并在排名册标“弃”，这是平台行政计分，不能转成实际对局分；取消后比分为空，是否重录须依据确认的原始赛果。

对未赛场次用重新导入编排测试延期/换场时，必须先锁定其他场次安排、通过离线冲突休息验收，再全量比较场次ID、比分、日期时间场地、小节和各端开关。隔离实测已验证一场延期15分钟并换场、其余三场比分保留；不能据此假定所有导入模式或团体子场均保留既有状态。控场`lsDcSave`与编排重导是不同路径，分别标注证据。

## 比赛控制、显示和通知

比赛控制集中管理小节、裁判/手机/出场名单各端开放，以及签名、弃权模式、PAD、领队填名单、证书、动态屏等选项。许多开关立即保存，审计时只读当前值，不能点击测试。小节分配与开放合同见[创建与发布](publication.md)。

自动检录通知有提前分钟、重复周期等设置；页面提示手机号、公众号关注和可解析的时间格式等条件。配置、删除配置、即时发送、测试发送都不属于只读。通知正文、渠道、收件范围、时点由用户任务决定，不能从“发布规程”推定。

2026-10-07新版手动检录通知还包含“已检录人员是否发送”，字段 `isYesJl`，当前页面初始值 `N`，选项 `N/Y`。这会改变接收范围；按本次要求核对，不因一次发送而永久改变默认策略。

新版控场连场检查按间隔场数筛选颜色：隔0场红、1场橘、2场紫、3场蓝、4场青、5/6场灰，并可显示间隔文字。这是平台返回字段 `JGCOUNT*` 的展示，不能据此推定已检查所有跨项目、未知晋级选手或真实分钟休息。编排页“重/连/场地调整”的“是否显示已完赛”初始为否（`ISYWC=0`）；验收全量赛程时应核对完整数据，不能把界面隐藏的已完赛场次当成缺失或空闲场地。

大屏存在经典、新版、横屏/竖屏、单场、桌面、直播、手机及多种检录样式。打开显示页用于核对；其中带检录或通知按钮的页面仍按写操作管理。证书坐标工具配置图片与文字位置，不证明成绩证书已生成或发布。

## 权限与账户范围

- 赛事人员权限 `/trialSsidCpyGlIndex`：角色、有效期、启用及默认场地；全局裁判库 `/trialCpyGlIndex` 与赛事授权分开。当前页提示裁判表导入下载适用于 PAD，不能当成手机裁判授权。
- 子账号 `/childZhGlIndex`：添加/编辑/删除、锁定/解锁、修改或重置密码；全局用户管理另有重置密码。普通赛事任务不附带这些账户操作，不能绕过菜单或后台角色限制。
- 财务管理、报名交易、充值、分账、银行商户是独立任务域。查询流水与退款、充值、收款渠道绑定、结算、补发分账分别判断；带“对账/初始化/测试”的按钮不自动视作只读。
- 退款前核对订单、实付/已退金额、通道、原因和用户授权；回读交易结果，不通过删除报名项推定退款完成。余额锁名单、积分生成 `zgYxJfGl/createJf` 也具有独立副作用。
- 导航中的会员中心、充值中心、AI助手和知识库需按真实权限使用。AI咨询/分析可能发送参赛信息并产生外部计算；应用AI编排结果是写操作，和本地离线排期分开。知识库保存不是生成当前赛事编排。
