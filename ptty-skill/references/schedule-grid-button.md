# 执行“生成场地数据”按钮

在[下载前检查](platform-workflow.md#下载编排信息前的场地数据检查)确认首次空网格、全赛无已编排场次及时间场地参数后执行。本操作是完成平台编排的前置步骤；已获授权且参数齐全时直接完成，不停留在提供预案或让用户人工点击。

## 页面操作

1. 进入目标赛事 → 赛事编排 `/trialSsBpIndex` → **赛事编排数据**标签（`ALLBP`）。若在“快速编排”（`KSBP`），先切换标签。
2. 点击橙色 **生成场地数据** 按钮。保存的客户端绑定是 `createBpHandler`，它才是页面方法；`createBp`是后端方法名，不应尝试调用不存在的`v.createBp()`。不要误点“自动生成编排场次”“AI智能编排”或“清空编排数据”。
3. 处理浏览器原生`confirm`：当前文案为“是否重新生成编排？确认后所有的编排数据将被清空，请谨慎操作”。这是该按钮的通用提示，首次空网格也会出现。仅在已确认空网格、全赛已编排数为0且本次编排授权覆盖初始化时接受；已有编排不能沿用首次初始化授权。该框不是页面里的HTML对话框，要用浏览器的原生对话框处理功能。
4. 确认后按钮处理器发出`op:bpGl, methodName:createBp, busData:{}`，读取已保存的赛事日期/时间/场地配置，并在响应后`alert`提示、刷新页面。它不弹出新的日期时间编辑表单；先核对已保存的配置，不向`busData`猜填日期时段。
5. 关闭结果提示，等待刷新并重新读取网格，比较日期、时间、场地、间隔和已编排计数。保护字段按完整快照复核；通过后点击“下载编排信息”，检查文件，再继续离线编排和导入。点击过按钮或收到成功提示均不等于完成。

找不到按钮时先查标签、页面加载和管理权限（客户端`isGly`控制显示），再报告具体缺口。浏览器原生框未处理不等于平台没有能力。

## 可执行辅助工具

`scripts/ptty_grid.mjs`使用Node.js 22+及现有本地CDP会话，自动切换上述标签、读取完整网格（最多1000行，超出时明确拒绝）、点击真实DOM按钮、处理一次精确匹配的原生确认框、观察请求和回读；不直接调用`createBp`代替点击。若已有网格，核对后复用，不点击生成。它不登录、不修改赛事基础配置、不自动下载/编排/分配小节。

```bash
node scripts/ptty_grid.mjs --session /secure/browser-session.json --event SS目标ID --grid 预期网格.json --out 场地数据回执.json --apply
```

`--apply`只用于现有用户指令已授权的平台编排任务；不是额外授权来源。会话格式与`ptty_readonly.mjs`相同。预期网格由已确认的日期、时段、场地和场序间隔展开，不让用户手填，示例：

```json
[
  {"date":"2030-01-01","time":"09:00","courts":["1","2"]},
  {"date":"2030-01-01","time":"09:30","courts":["1","2"]}
]
```

工具回执只证明按钮执行及网格/计数核验，仍需比较原场次CCH、签位、依赖并下载验证模板。失败或超时先回读，不再次点击；浏览器工具缺失时明确说明缺少执行能力，不把离线预检通过称为按钮执行成功。使用宿主浏览器工具时执行相同流程，无需另建CDP。

证据范围：按钮、标签、`confirm/alert`及请求字段来自保存的2026-10-08客户端；此前隔离赛验证过`createBp`生成及模板下载，本次新增按钮工具通过合成回归，以及隔离Chromium中的真实DOM点击、原生confirm/alert、生成回读和再次执行复用验证（所有页面请求由本地合成内容响应）；不代表新增线上赛事实测。
