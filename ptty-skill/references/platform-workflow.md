# 平台流程与核验

以下来自 2026-10-06 当前羽毛球模块观察。入口和字段可能变化，按本次页面确认；其他运动模块单独核验。读接口与写接口都可能使用 POST，不能按 HTTP 方法判断是否只读。

2026-10-07补充的完整功能导航、同名组件与模拟页面识别见[操作目录](operation-map.md)；变更依赖见[意图与状态](intent-and-state.md)，现场比赛、权限及财务细节见[现场操作](live-operations.md)。本页聚焦创建流程，不要求已有赛事从头重走。

|阶段|操作要点|回读验收|

|报名配置|报名管理维护项目资格、年龄、性别、限项、收费、截止时间；`RCOUNT` 是报名上限，`YBMRS` 为已报名统计|有效/待支付/退赛分别统计，双打按对；不拿9999当参赛人数|

## 下载编排信息前的场地数据检查

“已有比赛场次”和“已生成场地数据”是两个状态。赛事编排页 `/trialSsBpIndex` 的场地数据是日期、时间、场地和场序网格；只有比赛场次但没有网格时，直接下载编排信息可能返回“编排数据不存在”。按以下顺序处理：

1. 核对当前赛事和 `bpGl` 页面，读取完整网格及已编排/未编排计数，保存场次CCH、签位、依赖和既有安排。页面正在加载、筛选为空或请求失败不等于全赛网格不存在。
2. **网格已存在**：复用并核对日期、场地、时段及间隔后下载，不因未编排数大于0或一次下载失败重新生成。需改动既有网格时按本次调整范围处理。
3. **已确认网格为空且全赛已编排数为0**：在用户要求完成平台编排的授权范围内，沿用已确认的比赛日期、场地、各时段起止时间、午休和每场序间隔，切换到“赛事编排数据”标签，点击橙色“生成场地数据”按钮并处理原生确认框（`createBpHandler` → `bpGl/createBp`），无需为这一必要步骤再次要求确认。缺少关键参数时先补齐；请求字段取当前页面表单，不猜默认时段。该操作只初始化排期网格，不生成比赛场次、不抽签、不自动编排，也不替代导入后的“小节”分配与发布。
4. 生成后回读实际网格，核对日期、起止时刻、场地及间隔，确认原CCH、签位、依赖和已编排数未改变；通过后下载编排信息并重新打开文件。随后执行独立排期 → 导出平台模板 → 导入 → 逐场回读 → 按要求划分小节及发布。
5. **遇到“编排数据不存在”**：返回第1步核对。若网格存在，或空网格却已有编排，先查赛事绑定、筛选、加载状态及下载响应，不凭该提示删除、重建或重新抽签。生成超时先回读是否已落库；没有新证据不重复生成，网格仍未建立则报告具体失败，不无限重试。

具体按钮执行及脚本见[生成场地数据按钮](schedule-grid-button.md)。操作预检使用 `schedule.grid_initialize`（首次空网格）、`schedule.export`（下载编排信息）和 `schedule.import`；`schedule.grid`保留给一般网格配置/编辑。`grid_present`表示当前赛事完整读取确认网格存在，`grid_absent`表示确认不存在；`schedule_state_complete`表示无筛选/分页遗漏的网格及计数证据，`scheduled_matches_absent`表示全赛已编排数确为0，不能由“未开赛”推断。每步写入后重新读取事实，再预检下一步。

只读查询或仅下载任务不自动生成场地数据：指出缺少网格及所需初始化操作；现有编排任务的授权已包含首次初始化时应继续执行。`ptty_readonly.mjs`仍保持只读，线上初始化使用已授权的浏览器操作。

## 易混字段

- 多阶段方案需要逐阶段建立和核对；若 Excel 导入回执与完整列表矛盾，按[恢复流程](recovery-and-testing.md#方案导入异常的页面恢复路径)处理。已核验的页面新增第二阶段会关联第一阶段真实 `XMID`，不能用两个互不关联的普通新增项目代替。
- 平台可能压缩空白场序：本地占用场序1、3，回读可能为1、2，但实际开始时间保持间隔。导入验收按CCH逐场比较日期、时间、场地；休息按已确认的实际分钟或原网格口径验证，不按压缩后的显示编号误判。生成小节使用平台回读的真实CXH。
- 淘汰 `JJS/晋级数` 在当前样例表示需决出的名次数，填4对应独立三四名赛；循环中的同字段表示每组晋级人数。不能将录取奖励人数直接当需比赛决出的名次。
- 第二阶段人数须等于实际晋级席位。第一阶段循环与第二阶段淘汰记录不同 `XMID`，但仍属于同一离线项目。
- 保存抽签 Excel 未必写入种子元数据。已观察的 `cqGl/saveZzhHandler` 另保存 `seedList`，其中 `zzh、xmid、xmnm、sslx、ryid、ryid2` 来自当前名单；不可替换成“随机生成种子”。
- 小节已观察 `bpGl/createXj`，参数 `node、startCxh、endCxh`；这是写操作。场序编号连续不等于实际连续比赛，午休以已确认休息口径计算。
- 现场弃权支持单场/一弃到底等设置；导出成绩需保留具体状态，不把未赛、轮空和弃权都转成21:0。

排名模式从方案行 `PMMS` 读取。当前页面选项为 `ZC`（胜次、净胜场、净胜局、净胜分）、`SF-SUMVICMARK`（胜次、净胜分、净胜场、净胜局）、`SF-SUMMARK`（胜次、总分、净胜场、净胜局）；`SF-TOPMARK`在代码中存在但界面隐藏。空值不等于已确认默认规则。页面同时说明不同模式的胜次计算依据不同，因此将原值、界面说明和实际成绩一并交给离线成绩核验，不自行化简为统一胜场排序。当前静态界面未明确两人同分胜负关系、同分子集重算或弃权整组作废的全部细节；规程与实际记录仍需交叉核对。

2026-10-08补充合成实测，仅限4人单循环、单局21分上限30、`PMMS:ZC`：三人同胜次且互赛净胜分与全组净胜分排序不同的样例，平台选择全组排序；两人同胜次、相互胜负与净胜分相反的样例，平台按相互胜负排序。对应离线样例显式采用胜次、全组净胜局/分和`two_entry_tie_break:head_to_head_wins`；单局使净胜场与净胜局重合，这些证据不能推导多局、团体、其他排名模式或完全同分的完整规则。每次保留模式、完整比分及晋级回读。

排名设置表单同时提交的`ISHB`表示“中场是否换边”，不是同分合并或排名参数；只改排名时保留其原值。

## 可靠执行

写操作前从当前页面观察请求参数，并绑定明确目标赛事、输入版本和期望差异；既有授权覆盖本步就继续，不机械重复确认。保存、删除、锁定、初始化、自动抽签、自动编排和通知不是只读操作。

首次或部分失败回读后，按差异修复或恢复备份；同一错误无新增证据不重复提交。创建赛事需要先查是否已成功落库，避免超时重试创建两个赛事。结果修正涉及下游晋级时，列明依赖影响后在本次授权范围执行。

平台没有公开核验全部抽签和调度源码；使用兼容结果与回读验证描述，不声称完整复刻。收费、退款、通知发送、开赛及数据清空按用户明确范围执行，普通文件任务不附带这些操作。
