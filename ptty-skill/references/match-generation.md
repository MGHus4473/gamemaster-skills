# 已有签位但没有比赛场次

“完成跑兔赛事编排”先全量核对场次，复用既有结构；仅在确无场次且无签位时，在既有授权范围补齐必要的首次生成，再安排时间和场地。复用已确认日期、时段、场地数、时长和休息要求，不从历史测试赛套默认值。用户明确要求全部独立生成、只做文件或只读检查时，不调用平台生成。

## 正确入口与合同

入口是 **竞赛方案 `/trialGhIndex` → 勾选项目阶段 → 生成赛程 → 设置选项 → 生成赛程**。组件 `TrialGhIndex`；按钮受 `isGly` 控制，实际权限以当前页面为准。打开对话框的方法为 `createScHandlerOpenModal`，提交为 `createScHandler`：

```javascript
// ssid 取当前页面 v.ssid，不用明文赛事ID替换路由中的平台值。
// xmids 取本次勾选的真实阶段XMID；scModelData取当前表单确认值。
{
  headerData: {ssid: v.ssid, op: "scGl", methodName: "czSc"},
  busData: {xmids: selectedStageIds, type: "create", scModelData: confirmedModel}
}
```

优先通过可见按钮操作；使用已有会话执行组件请求时，先核对路由、组件、赛事、权限、当前方法和本次范围，串行使用 `utilPost` 并在结束后恢复共享请求对象。接口调用仍是线上写操作，不能因请求已由脚本准备就跳过核验。页面确认提示“此操作会清空所有赛程和编排数据”，因此此接口不是安全追加接口。

赛程管理 `/trialScGlIndex` 中的 `initScInfo` 是**重置**场次号、二阶段交叉方式或淘汰晋级数，不能用于首次创建。赛事编排 `/trialSsBpIndex` 只安排既有 CCH 的时间场地。17列场次导入及编排导入不能新建场次的证据，不能推导平台没有上述创建功能。`ptty_readonly.mjs` 只有读取能力，也不是平台能力全集。

当前观察到的选项如下，保留当前表单和用户选择，不用本表自动覆盖已有配置：

|字段|选项|客户端初始值|
|---|---|---|
|ZHSHOWMS|SZ数字、ZM字母组号|SZ|
|CCHGZ|0组别+组号+类型+阶段+附加+序号；1不含组号；2 U系列总决赛；3顺序号；5按轮且淘汰末轮倒序；6淘汰末两轮倒序|1|
|ISLKZZH|1轮空占组号、0轮空不占组号|0|
|FZFS|ZZZPT种子组优先平均分布、RSPT人数平均分布|ZZZPT|

## 按实际状态执行

先读取方案、名单、实际签位、编排和成绩，在赛程管理页用 `ptty_readonly.mjs --action matches`核对全量场次；读取方法、分页限制和旧组件处理见[只读工具](read-only.md#全量比赛场次)。名单、种子号、抽签模板的人员排名表不等于签位：`getCqResult.content`中的位置与报名项绑定才是已落库签位，`lsData.RYXXALLLIST`只是候选人员。

|完整状态|执行分支|
|---|---|
|已有完整场次|保留CCH、签位及胜负来源，直接进行独立排期；不再生成|
|无场次、无已绑定签位|在完整平台编排任务已授权范围首次生成，无需再要求用户手工完成前置|
|有签位却报告零场次|视为矛盾读数，复查赛事身份、无筛选汇总和逐项目对位表；不自动生成、不删签绕过保护|
|部分场次缺失或结构不符|核对选中项目及关联阶段影响，走[恢复评估](recovery-and-testing.md)；未证实追加语义前不把全赛生成当作补建|
|接口失败、分页不全、身份不符|状态未知，补读；不转换为零场次|

**首次生成**：确认方案关联阶段、人数、轮空和应赛场数，在竞赛方案页勾选真实阶段XMID及生成选项，提交一次。返回“存在未删除的抽签信息”时停止生成并复查既有场次；该提示不授权删签重试。超时先查落库。回读逐阶段场数、CCH唯一性、轮空、轮次、胜负者依赖和名次赛；新建的空签位结构与已绑定人员的签位分别验收，不要求新建空签位行数仍为零。

**既有场次编排**：保存原“项目/阶段、组号、位置、报名项、成员ID、种子、轮空”映射，交给 `gamemaster-skill`独立排期。按项目、阶段、轮次和双方来源映射CCH，不按行号拼接。首次空网格按[平台流程](platform-workflow.md)初始化，下载当前模板导入，再按CCH比较时间场地、休息、依赖及原签位。显示场序被压缩时以实际时间和原网格验收。出现非预期签位或依赖变化，停止后续写入并走恢复流程，不重新抽签掩盖差异。

已有授权不重复询问；收费、清空、重新抽签须有相应范围。平台状态待查或宿主缺少浏览器写入能力时，仍可依据已确认签位制作本地结构和排期，明确线上缺口，不统称“平台不支持”。

## 离线请求准备

`scripts/prepare_match_generation.py` 将已核实的快照生成上述请求，**不会连接平台**，也不负责登录或授予权限。它限定全赛事首次生成；已有场次的局部恢复使用上面的人工核验流程。本地输入及产物放赛事工作区，不放skill：

```json
{
  "mode": "platform",
  "event_id": "synthetic-event",
  "route_ssid": "synthetic-route",
  "project_ids": ["synthetic-stage-1"],
  "plan": {"event_id": "synthetic-event", "complete": true, "project_ids": ["synthetic-stage-1"]},
  "inventory": {"event_id": "synthetic-event", "complete": true,
    "captured_at": "2030-01-01T09:00:00+08:00", "matches": 0, "scheduled": 0, "started": 0, "results": 0},
  "draw_snapshot": {"binding": {"event_id": "synthetic-event"}, "complete": true,
    "captured_at": "2030-01-01T09:00:00+08:00",
    "rows": []},
  "sc_model_data": {"ZHSHOWMS": "SZ", "CCHGZ": "1", "ISLKZZH": "0", "FZFS": "ZZZPT"}
}
```

```bash
python scripts/prepare_match_generation.py 赛事工作区/首次生成输入.json --out 赛事工作区/首次生成请求.json
```

`inventory`须来自全量回读；`draw_snapshot`沿用[恢复快照](recovery-and-testing.md)格式，按稳定签位键保存已绑定报名项的完整投影字段；排除未绑定空位与轮空，但原始全签表另存用于结构核验。无已绑定签位时显式保存完整空快照。脚本拒绝缺项、跨赛事、未知选项、独立生成模式、已有/未知场次数，以及“零场次但签位快照非空”的矛盾状态；提交前须重新读数确认未变化。生成后比较已绑定人员映射是否出现意外变化，再独立验收新增场次和空签位结构。哈希相同仅证明投影字段相同，不证明遗漏字段或线上操作本身。

## 证据范围

2026-10-08再次核对官方公开客户端，资源路径及SHA-256与操作目录一致，确认上述按钮绑定、请求和选项。已有隔离实测记录证明该入口能从零生成4场淘汰赛，以及两阶段单打＋含轮空双打共21场；这些记录是在生成后完成抽签，**不能直接证明所有“已有签位再生成”情形均保签**。

随后隔离实测：零场次时抽签模板只有表头与人员排名表；首次生成4场后才有4个签位行。导入4个固定签位后，删除场次及重新生成均返回“存在未删除的抽签信息”，4场及签位保持不变。此证据说明当前普通流程不能通过带签位删除场次制造“有签位、零场次”，不能推广为所有版本/异常数据都不可能出现。

该4场合成赛随后完成独立结构/排期→模板导出→导入→API与平台Excel双重回读：半决赛09:00、决赛/季军赛10:00，每场30分钟，4种晋级结果均满足30分钟休息；原签位、CCH和依赖不变。显示场序1、3压缩为1、2，实际时间未变。此证据不代表已测试所有赛制或可带签位重建；正式赛事仅做只读核对。
