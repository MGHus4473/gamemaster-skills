# 用草料修改和美化赛事二维码

默认美化入口为用户指定的 [草料文本二维码](https://cli.im/text/other)。先按[平台取码流程](qr-codes.md)获取真实观赛网址和平台原图，再操作草料；跑兔负责二维码来源，草料负责样式。用户已指定采用草料时，上传任务所需的公开观赛链接、Logo和选定文字，无需为相同步骤反复确认；会话文件、管理端链接、登录凭据和报名资料不传给草料。

## 浏览器流程

1. 打开上述页面，清除编辑区旧内容，将平台`.url.txt`的**完整原值**作为文本内容输入。选择普通静态QR码；不要把标题/底部文字拼入编码内容，也不改用草料短链接或活码。仅更改外观时，扫码内容必须保持不变；若用户要求更换赛事入口，先重新核对目标赛事并从跑兔取新链接。
2. 点击“生成二维码”，读取实际预览；`/text/other`生成后转到`/text`是本次观察到的正常导航。点击**上传Logo**或**二维码美化**，当前实际打开页面内“二维码样式编辑器”；上传Logo还会打开“选择Logo”弹窗。在该弹窗上传图片，出现“裁剪图片”时核对裁剪范围并点“确认”。不要停在文件已选择，也不默认跳到独立站。页面顶部“美化”链接另可进入[美化系统](https://mh.cli.im/)；如转到新页，核对是否带入原链接，不能沿用演示码。
3. 复用用户已上传的Logo，调整位置、尺寸、码点/码眼颜色及背景。底部文字的当前路径为**添加文字 → 添加码下方文字 → 请填写内容**；标题可用码上方文字。保持“编码内容”仍为平台原链接，核对“自动取码名称”开关与实际文案，避免名称覆盖用户文字。完成后点击**保存样式并返回**，主页会出现“编辑样式/修改字段”，再核对最终预览。此按钮应用当前样式，与“另存为我的样式”保存到账户不同。
4. 默认采用清晰的深色码点、浅色背景和普通QR；有Logo选H/30%纠错，四周静区至少4模块。页面当前示例边距为3个色块，交付前要调整，不能照搬示例值。用户未给样式时采用简洁正式的标签、适中Logo，底部文字采用已给定内容；无文字要求时不擅加宣传语。
5. 下载实际成品PNG；需要打印时可同时下载页面提供的PDF/SVG等格式。保存平台原码、原始链接、草料下载成品和验收回执。保存样式到草料账号、付费或印刷下单按用户任务范围执行；需要登录时沿用可用会话，遇登录/验证码则报告具体阻塞，不声称美化已经完成。
6. 使用下述工具验证**草料下载的原文件**，不要再生成本地码替换它。核对Logo、文字、边距及配色；解码必须等于跑兔原始链接，拒绝演示码、错误赛事、协议被更改或短链替换。PDF/SVG若交付，也需渲染其自身成品并验证，不能用同批PNG的成功代替矢量文件验收。

```bash
python scripts/verify_qr.py --image 草料美化二维码.png --url-file 比赛二维码.png.url.txt --out 草料二维码验收.json
```

工具依赖`Pillow、zxing-cpp`，只读图像并输出文件/负载哈希，不修改图片、不保存完整链接到回执。成功解码不证明实际手机页面可用，微信/相机扫码另记证据。

## 范围与失败处理

- 跑兔裁判微信小程序码不进入普通文本生码流程。保留平台原码体；若草料不能保持原图，仅做外围排版或按用户接受的本地方式处理，不转换为普通QR或遮盖原码。
- 未核验草料的稳定自动化API，使用当前网页可见操作。草料可用时按本流程完成，不静默退回本地生成；网站或登录确实受阻时，交付平台原码并说明差异，本地`qr_export.py`仅作为明确标注的备选或用户指定的离线方式。
- 此流程不改动跑兔的小节、规程、名单或发布开关。组合任务中分别报告平台发布、取码、草料美化、最终解码及实际扫码的完成状态。

核验于2026-10-08：[文本生成器](https://cli.im/text/other)列出Logo入口、纠错、尺寸、边距和下载格式；[美化系统](https://mh.cli.im/)说明Logo/文字/背景调整及样式保存。同日匿名浏览器合成实测已完成文本生成、上传/裁剪自定义Logo、4模块边距、H纠错、码下方文字、保存样式、点击下载图片；下载PNG经目视核对及解码，原始测试链接保持一致。该证据不覆盖所有样式、账户样式保存、矢量下载或真实手机扫码。
