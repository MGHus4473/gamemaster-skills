# 时间与场地编排

把已有比赛安排到日期、场序、场地及小节。比赛结构、抽签和实际排期分别处理；沿用当前签表和本地稳定场次ID，不为排时间而重新抽签或生成比赛。计算和输出均在本地完成。

## 编排前问询

先读取规程、名单、签表、原日程与用户已有回答，再询问影响本次编排的缺项。先问“是否有必须遵守的安排”，并给出下表的相关选项，不一次列出所有高级功能。确认关键条件后生成正式表；可先做容量测算。

|要确认的内容|给用户的选择与说明|
|---|---|
|日期与场地|每天日期、场地号、各时段可用场地；是否临时停用、项目专用或决赛指定场地|
|按时间还是场序|固定开赛时间；仅按场序依次推进；时间为预计、现场滚动开赛。不要将预计时间当作实际结束时间|
|每日时段|上午/下午/晚上分别几点开始、几点结束；午休多久；开幕式、用餐、检录和颁奖是否占时段|
|场序时长|每场序几分钟；不同项目是否不同；是否已含热身、换场、记录比分缓冲|
|小节|按上下午/晚场、日期或项目阶段划分；小节与场序编号是否跨日连续|
|运动员冲突|跨单、双、团体统一识别人；只检查已确定选手，或检查所有可能晋级选手（通常建议后者）|
|最小休息|至少空几个场序，或从上一场结束至少休息几分钟；这是必须条件还是尽量满足；午休及隔夜是否计入；特殊组别是否更长|
|主要优先目标|默认整体尽早结束、压缩总场序；可明确改为指定单项先结束，或补充减少等待、按组集中、同轮同步、决赛集中展示|
|固定安排|不可调整的场次/开赛时间；晚到早退；项目截止时间；半决赛是否同步、决赛与季军赛是否同时进行|
|交付|默认现有赛事编排Excel模板并另附审阅表；用户指定模板时优先遵循；是否需要额外平台交接文件|

适合一次提问的表述：“请确认日期及场地、每天可比赛的时段、按时间还是场序、每场序长度与休息；你希望混双先结束、整体尽早结束，还是决赛集中到最后？有无固定场次或晚到人员？”已有答案不重复问；把预计参数及默认偏好明确记在参数单。

默认先满足冲突、依赖、时间窗口及确认的休息，再尽早结束整场赛事，压缩占用场序；单项尽早收尾作为后续比较条件。“混双优先”不自动表示愿意拖晚整场赛事；只有用户明确选择单项完成时间高于整体完成时间时，才用`objective: project_first`。各项目可穿插利用休息时段；不把优先结束解释为连续出场。

## 约束及补充策略

硬条件先于优化目标：

1. 每场恰好一次；同一场地同一时间不能占用两场；不能超出可用日期、时间、场地。
2. 双打、团体按实际运动员ID展开，跨项目统一查重。姓名相同不直接合并，ID不同时仍应核实已知兼项映射。单位回避属于抽签，不等于“同单位成员不能同时打球”；陪同教练冲突须另行指定。
3. 胜者/负者来源和前后阶段有向依赖完整；轮空不是一场比赛。下游开赛必须在上游结束并满足确认的休息后。决赛与季军赛分别依赖两场半决赛，可同时安排时无需互相等待。
4. 固定安排、人员可用时段、场地区间和已开赛/已结束场次按要求锁定。调整时仅重排获准调整的未开赛比赛。
5. “至少空1个场序”：15分钟网格中09:00–09:15比赛后，通常最早09:30再上场。区分实际时间休息与有效场序间隔；采用时间口径时11:45–12:00后15:00出场已有3小时休息。12:00及16:00作为结束边界时，不再在该时刻安排新场。
6. 只检查已确定选手时，待定晋级者的跨项目冲突属于待复核项，不能宣称对所有赛果均无冲突。所有可能选手模式需正确处理互斥胜负路径，不能仅因决赛和季军赛候选集合相同就判重场。

“尽量避免连赛，无法避免则接受”属于可放宽偏好；规程或明确确认的最小休息仍是硬条件。先在不放宽休息的条件下寻找完整方案。只有可核实的约束冲突，或用户接受了休息不足的具体备选方案，才在允许范围内调整休息参数，并列明运动员、前后场次和实际间隔；不要把一次启发式搜索失败或单纯想提前结束当作“无法避免”。无论休息如何调整，同场序重场和前后轮倒置始终禁止。

连场检查至少分别报告同场序重复出场、相邻出场、实际休息不足。午休后紧接下一个编号可能已有数小时休息，不应误判为高强度连赛。隔一个场序连续打多轮、每天打很多场属于另一种负荷；需要额外每日场数/时窗限制时先确认，不能把满足15分钟休息等同于已评估全部体能负荷。

可选优化项按赛事需求启用并排优先级：

- 项目尽早收尾、整组集中/组内按轮推进、组别或项目交错、同一轮尽量同步。
- 减少等待和跨场移动、场地相对固定、兼项较多的选手提前安排前轮。
- 决赛集中、指定展示场、同奖项比赛同步、赛后留颁奖和申诉处理时间。
- 预留机动场序/机动场地、高耗时项目增加时长、限制运动员每日场数。
- 裁判、教练、计分设备、团体子场并行及共享成员作为额外资源约束。

后三类复杂规则需要相应数据和专项核验，不能只写进备注就声称已满足。现有脚本功能见下；未实现的约束先扩展适配器/算法或进行可核验的人工锁定，再交付。

## 本地生成与验收

含预留名额时，按填满后的比赛结构预估占场，但`athletes`不填虚构人员；未知身份的跨项目冲突暂不能保证。结构依赖与前后轮休息仍要检查。替换真实选手后，用统一运动员ID重算所有相关项目的重场、休息、可能晋级及上下游依赖，按原确认口径验收；不能因为签位没变就跳过。未填预留按确认截止规则转为轮空/退赛后再更新实际比赛与场次统计，不能录成虚构比赛成绩。

`scripts/schedule_engine.py` 无网络依赖，使用固定随机种子的多次列表调度，尝试项目集中、跨项目关键依赖优先及扰动排序。默认`objective: makespan`，在完整且满足休息的方案中先比较整场实际预计结束时间，再比较指定单项完成时间、使用场序数及各单项收尾。显式`project_first`才交换前两个目标，且必须指定`priority_projects`。算法不会证明全局最优；未排完标记`search_incomplete`，不把搜索未找到方案称为数学无解。

固定时段或可用窗口只剩一个合法场序时，先保留该场次的人员休息，并优先安排到当前场序；灵活场次不能提前占用它需要的休息间隔。场地选择兼顾仅有单一可用场地的比赛。此处理仍是启发式，不保证复杂固定窗口一定找到完整解。

支持统一场序网格、多个日期/小节/午休、分时段可用场地、项目优先级、确定或可能运动员冲突、按分钟或有效场序休息、前置比赛、指定场地、最早开始/最晚结束及固定位置。每场仅占一个网格：`duration_minutes + turnover_minutes <= slot_minutes`。超过时长、多格占场、裁判资源、每日场数上限、团体动态阵容目前需扩展，不能截短占场时间来通过检查。

```bash
python scripts/schedule_engine.py input.json schedule.json
python scripts/export_event_tables.py schedule input.json schedule.json schedule.xlsx
```

导出需要`openpyxl`。本地算法对运动项目通用，具体时长、休息和比赛规则来自当前规程，不内置所谓通用官方15分钟规则。

输入顶层：`event_id、courts、slot_minutes、sessions、rest_basis、rest_minutes、rest_scenes、conflict_scope、matches`。`sessions`项含ISO格式`start/end`、正整数`section`，可另含`courts`；结束时间不含新的开始场序。`rest_basis`为`elapsed/active_scenes`，`conflict_scope`为`known/possible`；可指定`objective、priority_projects、random_seed、attempts、turnover_minutes`。日期时间统一为赛事当地时间、精确到整分钟，不附时区偏移；时区另记元数据。时长、休息参数采用整数分钟/场序，避免小数被导出为整分钟后造成重叠。

每场至少含`id、project_id、athletes、predecessors`；`athletes`只放已确定的运动员ID，可能模式另给`possible_athletes`，其中必须包含已确定人员及所有前置比赛候选人。可指定`duration_minutes、allowed_courts、not_before、finish_by、fixed`；`fixed`使用输出字段`slot_index`（从0计）、`court`等。

对阵的结构化`sides`里，`kind: winner/loser`必须同时提供`match_id`，且该ID存在于`predecessors`；已确定选手及候选集合与侧信息核对。不能只写“胜者”显示文字而不给来源关系。导入适配器须以签表或分组晋级规则核对依赖是否齐全；没有来源信息时算法无法自行猜出漏项。循环晋级等复杂来源还需独立建模。

`outcome_disjoint_pairs`不能作为绕开冲突的开关。当前仅接受可由结构化侧信息证明的同一组前置场次相反胜负来源，且各前置场次候选互不重叠；无证据的豁免直接报错，已确定人员重叠也直接报错。其他名次赛分支需补充对应证明，不能人工标记后跳过检查。

本地Excel使用本地场次ID；可附`project_name、code、round、rank、sides`等显示信息。待定方显示结构化来源，不虚构姓名。平台ID仅属于可选交接映射。

容量测算使用实际比赛数及占场时长。导出前重算约束，校验无漏场、无重场、无非法依赖、无窗口/休息违规；未排完不输出正式导入表。前后依赖分别检查是否严格在前、是否满足休息，即使休息设为0也不能同场序安排。提出加场地、延时、增加比赛日、调整固定安排等选择，不擅自牺牲休息。

当前Excel适配器验证了固定时间表。纯场序表可沿用本地依赖及场序休息计算，但须按用户模板调整时间列和导出核验；滚动开赛以实际结束时间重新检查休息，不承诺初始估时就是现场执行时间。
