# 独立抽签

在本地将报名项放入签位或循环小组，使用已确认种子、轮空和回避规则。已有签表可作为固定位置约束。抽签结果交给比赛结构生成器，随后独立排期。

## 输入确认

沿用已确认项目和报名项，补齐当前抽签真正缺少的信息：

- 运动、赛制、阶段、参赛人数，淘汰签位与轮空，或各组容量。
- 种子名单及序号来源。无种子时全部设0；不得把报名顺序、技术号或原签号当作实力排名。临时测试种子须有用户授权，并在审阅表和记录中标明。
- 回避单位如何定义：完整队名、俱乐部，还是明确的上级单位映射。一队/二队不自动合并。双打作为一个完整报名项，不拆开分配；跨单位组合先明确回避口径。
- 是否重新抽签，是否有已锁定签位，以及哪些约束是硬条件。

保存输入版本，开始前生成并记录随机种子。相同输入和随机种子得到同一结果；不得为了偏好某个对阵反复重抽而不留痕。

并组后沿用最终报名项ID，重新确认种子依据，不拼接原各组的1号种子。预留项按 [预留与替换](reserved-entries.md) 使用唯一报名项ID、显示标签、`seed:0`、`club:""`进入本地抽签；空单位表示尚未知晓，不把所有预留项当同一俱乐部。预留占一个参赛位置，与轮空不同，不能重复扣除人数。替换后保留位置，检查真实单位回避和种子冲突；已有局面不能通过重抽签静默解决。

## 本地算法与边界

使用 `scripts/draw_engine.py`，仅依赖Python标准库，支持：

- 淘汰签位：1号种子在顶端、2号在底端；3—4号进入剩余两个四分区，5—8号进入剩余八分区，依次分层。层内随机选择可行位置，兼顾单位约束。
- 内置羽毛球技术表中2—32个报名项的轮空位置。更多人数的非满签项目须提供明确轮空表；满签及显式轮空可使用更大签位。种子数量由已确认方案给定，不自动选人。
- 单位分布：在选定层级的每个分区中，同单位人数均处于 `floor(该单位人数/分区数)` 至 `ceil(...)`。默认覆盖半区、四分区直至首轮对位区。两个同单位报名项分至两半区；人数多时允许不可避免的同单位相遇。
- 循环分组：按明确组容量入位，组间同单位人数差不超过1；种子按蛇形分组并占对应组内位置。该模式在本地执行。
- 固定签位、固定组、确定性重放和完整性核验。

采用随机顺序的约束搜索；保证成功结果满足声明的约束，不宣称对所有可行签表均匀采样。不能满足硬条件时报告无解；达到节点上限时报告搜索未完成，二者不能混淆。不得自行放宽单位规则。必要时请用户选择调整固定签位、回避层级或种子设置。

例如6人、8签位，A单位3人、B单位3人，A的1/2号种子分别占据两端的轮空单人四分区，B剩下三个选手就无法占据三个不同四分区；严格四分区均衡会报冲突。这不是通过多次换随机种子就能解决的问题。

种子位置依据已核验的羽毛球配置；乒乓球、网球或赛事自定规则使用明确的 `seed_positions` 和 `byes`，不要默认套用羽毛球表。自动推导二阶段AB/AC/AD交叉及同源小组回避尚未实现；已确认的交叉表可交给 `bracket_engine.py` 按表生成，见 [比赛结构](brackets.md)。

## 运行与数据结构

```bash
python scripts/draw_engine.py input.json draw.json
python scripts/export_event_tables.py draw input.json draw.json draw.xlsx
```

本地Excel导出仅需openpyxl，不需要系统ID。

最小输入：

```json
{
  "event_id": "local-event",
  "random_seed": "本次抽签开始前记录的随机值",
  "test_seeds": false,
  "projects": [{
    "id": "project-1",
    "name": "男子单打",
    "sport": "badminton",
    "format": "knockout",
    "seed_profile": "badminton_bwf",
    "entries": [
      {"id":"e1","name":"选手甲","club":"单位A","seed":1},
      {"id":"e2","name":"选手乙","club":"单位B","seed":2},
      {"id":"e3","name":"选手丙","club":"单位A","seed":0},
      {"id":"e4","name":"选手丁","club":"单位B","seed":0}
    ]
  }]
}
```

可选淘汰字段：`bracket_size`、`byes`、`balance_levels`（如`[2,4]`）、`seed_positions`（种子号→允许签位列表）。报名项的`position`为固定签位。`format:"groups"`改用`group_sizes`和`seed_policy:"snake"`，报名项可指定`group`及组内`position`。

输出JSON保留输入规范化SHA256、随机种子、种子位置及单位分布。平台导入适配器位于`ptty-skill`，不属于本地抽签的必要步骤。

种子/轮空内置羽毛球配置来自已核验的BWF技术图表（2020-02-19版），不是对所有项目通用的默认规则。乒乓球、网球、匹克球用本场确认的`seed_positions/byes`；无种子也须确认非满签时的轮空政策。

新增输入逐项目明确sport。非羽毛球淘汰使用`seed_profile:"custom"`和本场确认的`seed_positions/byes`，程序会拒绝误选`badminton_bwf`；旧未带sport的历史羽毛球文件保留兼容。
