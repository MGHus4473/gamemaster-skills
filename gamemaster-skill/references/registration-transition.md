# 报名转竞赛：并组、取消与补充通知

报名方案用于收集意愿、资格和费用，竞赛方案用于实际比赛，两者可以使用不同组别和不同赛事。保存原报名版本，在独立竞赛名单中应用调整；不能覆盖原始报名来掩盖差异。与 [参赛名单制作](participant-roster.md)、[竞赛方案](competition-plan.md) 配合使用。

## 先核对并询问

从规程、报名材料和补充批次提取每组真实有效报名项数，区分未缴费、待审核、退赛、重复和材料缺失，说明采用的口径。零人组也进入统计。预留不计入真实人数，双打按对、团体按队，兼项人员的全赛事人数去重另计。

只补问本场缺项，可提供以下选择及影响：

| 决策 | 提问与建议 |
|---|---|
| 开赛门槛 | 用户常用基准为8人；本场是否采用？双打/团体建议按8对/8队讨论，须确认，不能当协会统一规定。另确认保障场数和低于门槛能否独立开赛。 |
| 并组范围与顺序 | 哪些组可合？优先同项目、资格接近的相邻组，但相邻年龄、同龄男女、水平组哪项优先由本场决定；达到门槛后一般保留原组特色，不继续无必要合并。 |
| 不可合并及取消 | 哪些组必须独立？仍不足时选择延期、改赛制、确认例外、取消或自愿转项；资格/年龄适宜性不能靠让分自动满足。 |
| 让分 | 哪些类别对阵让分、方向和分值？跨性别与跨年龄同时出现时替代还是叠加？可明确0分，不套历史分值。 |
| 权益与确认 | 奖励合并还是另计原组名次？接受并组、转项、退出截止及费用处理是什么？原组另计排名须有可执行排名算法，不能从混合淘汰名次直接拆奖。 |
| 预留与输出 | 是否需要预留、各项目1～3项还是其他数量？见预留参考。通知沿用已选格式；未确定时问Word/PDF/MD/文本/LaTeX。 |

用户已确认的原则是“并组、取消、让分按具体比赛确认；预留标为预留名额且不当真实运动员”。此原则不等于任何一场的具体参数已获确认。

## 形成可追溯的最终方案

1. 固定输入版本和资格/缴费口径，统计各原组人数、可并范围及容量。
2. 提供少量候选：最终组别、来源、实际人/对/队数、距门槛差额、资格变化、让分、保障场数、预计总场数和奖项影响。先检查允许合并，再争取达到门槛，随后比较公平性、比赛体验与场地时段。不为凑数任意扩大年龄跨度。
3. 确认后建立原组→竞赛组映射及逐项变更清单。每条原报名项只有一个明确去向：进入目标、取消/退出，或已退赛；新报名与转项分别标来源。多组报名的同一人合并到同一项目会重复，必须明确保留哪项、如何处理费用；双打换搭档不静默产生新组合。
4. 核对每个目标人数等于流入项＋新增项−撤回项，再加入确认预留项。不要用原报名总数直接推算最终总数，也不要把未匹配项当作退出或预留。原年龄、性别、单位、原组标签及真实运动员ID保留，用于资格和让分。
5. 重新确定分组、晋级、录取名次、种子、同单位回避、兼项和容量；并组后原1号种子不能自动全保留。费用记录与竞赛席位分开，取消或转组不表示系统已退款。
6. 从同一确认版本输出最终名单、竞赛方案、映射/变更清单及补充通知。需要交接平台时另附目标ID映射，不改变本地标识。

报名截止后增补、抽签后变更、开赛后退出是不同情形。开赛后涉及成绩的变更按规程处理，不能通过删除报名重建比赛绕过赛果。待核实的报名先列清单，不擅自剔除后声称全量已完成。

## 让分按类别对确认

羽毛球并组需要保留原性别、原年龄/水平组和双打组合分类。双打年龄可能按较大者、两人和、分别满足区间等定义，按本场规程；不能凭组名推定。

采用明确的对阵矩阵，例如行甲对列乙的值为甲获得的起始分，正数为甲受让、负数为乙受让，同类为0。每种可能类别对都写数值，双方方向互逆；不要求传递性，不把“男双让混双5、混双让女双4”推成“男双让女双9”。特殊年龄组合可覆盖一般性别规则，是否相加必须明确，不接受含糊的“多让几分”。

同时确认适用项目/阶段、每局还是整场、目标分和封顶、领先要求、间歇/换边、发接发与单双数场区、循环排名如何使用让分后的比分。脚本目前仅校验每局起始比分模式；其它让分玩法按实际规则扩展。某阶段目标分不同则另建配置，不能全场套同一上限。对场比分与记分表要能提示适用让分；平台是否能自动处理另行验证。

## 补充通知内容

正式文稿使用 [内容模板与校验](regulation-content.md) 的补充通知模板。下方脚本 `notice` 产生报名转换事项底稿；从同一已确认转换结果提取映射、让分和影响，补齐原规程版本、主送对象、条款调整及生效/办理窗口后再生成正式文件。不要把转换底稿的生成成功等同于整份通知内容审查通过。

引用原规程的明确版本，列生效时间、发布主体、被修改条款；来源冲突先确认效力，不单凭文件修改时间。正文至少覆盖：

- 原组与新组对照、取消组及去向；真实人数与预留分列（无需公开身份证等明细）。
- 参赛资格、赛制/晋级、计分让分矩阵、录取与奖项；不变项可以明确沿用哪一条。
- 确认/退出窗口、费用处理、补录/替换截止、逾期未填名额处理。
- 赛程是否重发及公布渠道，已发布版本的替代范围。

同步生成文件不代表已发布。外部发布与通知由对应平台skill按用户要求执行。格式沿用 [规程输出](regulation-output.md)。

## 本地工具

`scripts/registration_transition.py`依赖名单校验模块及openpyxl，接受已审核的标准报名JSON，支持完整组映射、逐项转组/取消、预留、人数校验、让分矩阵、补充通知和替换。团体模板、自动资格认定、任意并组优化求解与平台写入不在该脚本范围。

```bash
python scripts/registration_transition.py apply 报名.json 确认方案.json 转换结果.json
python scripts/registration_transition.py notice 转换结果.json 补充通知.md
```

转换结果包含`roster/ledger/summary/plan/source_projects`，提取`roster`为独立JSON后用`participant_roster.py export`生成模板Excel。JSON字段见 [调整方案数据](registration-transition-data.md)。命令拒绝覆盖旧输出；原报名对象不被修改。
