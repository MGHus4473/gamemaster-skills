# gamemaster-skill

独立于赛事平台的本地赛事工作流，适用于羽毛球、乒乓球、网球与匹克球。读取用户材料、确认关键参数，制作可核对、可继续修改的赛事文件。

## 功能

| 阶段 | 工作与输出 |
| --- | --- |
| 规程与规则 | 区分必填信息、补充条款与可选表述；生成规程、补充通知和规则解读 |
| 报名与名单 | 整理表格、文档、文字及可识别图片；保留原件来源、增补和身份映射；输出模板名单 |
| 报名调整 | 保留原报名与最终比赛的对应关系；按确认方案并组、转项、取消组别和配置让分 |
| 预留名额 | 估算增加名额对容量与场数的影响；预留项不充当真实运动员，替换后复核 |
| 竞赛方案 | 确认项目、人数单位、赛制、分组、晋级及名次赛；生成 Excel 及完整规则数据 |
| 抽签与对阵 | 独立随机种子、种子位置、单位分散、轮空、签位与前后依赖；生成本地场次 ID |
| 编排 | 根据场地、时段、小节、休息、兼项和固定安排生成日程；核对约束来源、前移与换位改进，输出指标及等待原因 |
| 成绩与文稿 | 校验比分、计算循环名次与淘汰名次，导出成绩；制作开闭幕致辞、主持词与颁奖词 |

业务入口见 [SKILL.md](SKILL.md)。模板与专题按任务加载，避免一次阅读所有参考文件。

## 使用

将本目录完整加载到支持 skills 的宿主。把赛事文件放在独立工作区，并向宿主提供其位置及所需输出。示例：

> 用 gamemaster-skill 处理这两版报名表，核对增补、重名与搭档关系。按我提供的模板制作最终名单，并另列待确认项。

> 用 gamemaster-skill 制作网球赛竞赛方案与签表。按规程使用短盘制，保留抢七设置；不要将其压缩成羽毛球的局分字段。

> 用 gamemaster-skill 核验这份赛程，重点检查同一人跨项目重场、休息不足及决赛早于半决赛。保持签位，输出修订表与变更记录。

先读已有材料，再补齐会影响结果的缺项。模板优先级为本场用户模板、明确采用的赛事模板、内置默认模板；关键参数未确定时交付草稿或缺项清单。

## 本地工具与依赖

| 用途 | 工具或依赖 |
| --- | --- |
| 抽签、对阵、排期、成绩；JSON/CSV/MD/文本 | Python 3.10+；核心计算使用标准库 |
| 名单、报名调整、Excel 输出与模板处理 | `openpyxl`，见 [requirements.txt](requirements.txt) |
| Word | Node.js 20+、`docx`，见 [package.json](package.json)；另备中文字体 |
| 简单 PDF | `reportlab` 与可用中文 TTF 字体 |
| 简单 LaTeX PDF | 本地 XeLaTeX 或 Tectonic，已安装或缓存的宏包与字体 |
| 旧 XLS、扫描件或图片输入 | 按材料准备相应读取库、本地 OCR 或宿主视觉工具 |

依赖可在联网准备阶段安装，脚本运行时不自动下载。完整要求见 [运行环境](references/runtime.md)。在本目录检查环境：

```bash
python scripts/check_runtime.py --feature core
python scripts/check_runtime.py --feature xlsx
python scripts/check_runtime.py --feature docx
```

智能体按参考文档生成并校验结构化输入，再调用工具。例如：

```bash
python scripts/render_regulations.py 规程.json --format docx --output 规程-v1.docx
python scripts/participant_roster.py export 名单.json 名单.xlsx
python scripts/schedule_engine.py 编排输入.json 编排结果.json
python scripts/results_engine.py 含真实赛果的对阵.json --output 成绩-v1
```

示例输入与输出路径应替换为赛事工作区中的实际路径，输出使用新版本。完整流程见 [文件工作流](references/file-workflow.md)；各脚本的输入结构见对应参考与 `--help`。

## 格式与算法边界

Word 默认 A4、四边 25 mm 页边距、宋体正文、黑体标题、Times New Roman 西文；正文 12 pt、首行缩进 2 字符、1.5 倍行距。分级标题、条目悬挂缩进、表头重复、表格防跨页断行、附件和页码有独立规范，可用样式配置覆盖。详见 [Word 排版](references/word-formatting.md) 与 [文档输出](references/regulation-output.md)。

内置 Word 渲染器不直接导入任意 `.docx` 模板，也不处理图片签章、合并单元格等复杂元素；这些要求需使用合适的文档工具并复核。内置 PDF/LaTeX 后端支持简单结构，复杂分级条款和附件应通过本地办公软件导出或扩展排版。缺少办公软件时会明确标注仅完成结构校验。

对阵引擎支持单/双打单循环、双循环、单淘汰及分组循环后淘汰，可配置季军赛与前八完整名次赛。复杂团体阵容、双败和额外名次体系需另行建模。排期采用统一时间网格，每场占一格；应先根据实际单场时长选择网格。启发式编排不保证全局最优，未找到排法也不等于数学无解。

运动员与报名项分别使用稳定 ID；双打两人分别参与冲突校验，姓名不能充当唯一身份。轮空、未赛、弃权和退赛分别记录，不虚构已赛比分或冠军。规则解读依据已提供或已核验的版本；离线运行不声称已经核对最新规则变更。

## 与跑兔协作

单独使用本 skill 不需要跑兔账号或客户端。需要上线时，按 [文件交接](references/file-workflow.md) 输出文件、版本、哈希及本地 ID，由 `ptty-skill` 核对平台模板并绑定当前真实 ID。平台操作结果再作为新版本材料回到离线流程。

赛事原件与成果放在 skill 目录外。仅保留任务所需的个人信息，公开导出另行脱敏；账号、密码、令牌与浏览器会话不写入 skill、交接文件或测试样例。
